WHY SECURITYGUARD

Built for restraint,
not bravado.

Multi-signal scoring

Four independent detectors feed a centralized confidence engine. No single signal can trigger a response — at least two evidence categories must agree.

Debounce & cooldown

Detection requires sustained evidence across samples. Per-episode cooldown prevents repeat firing. Recovery debounce ensures stable clearing.

SSR-safe by design

No module-level browser access. start() becomes a controlled no-op on the server. Works in Next.js, React SSR, Vue, Nuxt, and Node.

Zero dependencies

No runtime dependencies. Tree-shakable ESM with CJS fallback. TypeScript declarations included. Small enough to audit in an afternoon.

Accessible actions

Overlay and block layers use native <dialog> with ARIA roles, focus containment, and keyboard handling. SPA state is preserved.

Privacy-first reporting

Optional backend reporting sends only a minimal whitelist. No cookies, tokens, form data, or paths by default. Non-blocking with timeout and abort.

DETECTION ENGINE

Four signals.
Three categories. One score.

Each detector operates independently and returns structured data. The scorer combines them — but correlated signals share a category, so one browser pause can't count twice.

LAYOUT+20

Window dimensions

Compares stable outer/inner window gaps. Suppresses evidence during resizing, mobile, zoom, and orientation changes.

FP risk: Browser chrome, sidebars
TIMING+40

Debugger timing opt-in

Measures execution delay around a debugger statement. Rate-limited and disabled by default — an attached debugger can pause indefinitely.

FP risk: GC, CPU contention
INTERACTION+15

Keyboard shortcuts

Observes F12, Ctrl+Shift+I/J/C, Cmd+Option+I/J/C. Never prevents default behavior. A shortcut is a signal, not proof.

FP risk: Custom app shortcuts
TIMING+25

Browser behavior

Foreground scheduling drift beyond expected intervals. Resets on focus/visibility changes. Delays over 10s are discarded as suspension.

FP risk: Long tasks, CPU load

RESPONSE ACTIONS

Your policy,
your response.

Access Restricted
Possible inspection activity detected.
Reload page

Overlay

Accessible modal dialog with a reload button. Focus is contained, siblings become inert, SPA state is preserved.

action: 'overlay'
Access Restricted
Interaction blocked.

Block

Full-screen blocking layer without a reload button. Prevents interaction without destroying application DOM or state.

action: 'block'
→ /security-blocked

Redirect

Same-origin location.replace() to a safe destination. HTTP(S) only, credentials rejected, no redirect loops.

action: { type: 'redirect', url: '/blocked' }
handler(event)→your code

Callback

Monitoring-only mode. Receive detection events without any SDK layer. Perfect for logging, analytics, or custom UI.

action: { type: 'callback', handler }

!

Visibility, not invincibility.

Browsers have no official "DevTools is open" API. Detection is not guaranteed. Resizing, sidebars, CPU load, and keyboard shortcuts can produce ambiguous signals. Determined users can bypass all client-side checks.

SecurityGuard is a deterrent and monitoring layer. It is not authentication, authorization, DRM, or API protection. Keep secrets and sensitive validation on your server. Never make irreversible account decisions based on a detection score.

API REFERENCE

Small surface.
Full control.

start(config?)

Replace configuration and start monitoring. Returns the instance.

stop()

Complete teardown — listeners, timers, reports, layers.

pause()

Suspend observation. Preserve config and subscriptions.

resume()

Restart from paused with fresh evidence.

getStatus()

Snapshot: lifecycle, state, score, signals.

getScore()

Current 0–100 heuristic confidence score.

on(event, handler)

Subscribe to detected / cleared / violation events.

off(event, handler)

Unsubscribe a previously registered handler.
